# evals

The task evals of [PLAN.md](../PLAN.md) §6.2, written from the spec only (PLAN.md §4 and §6, [contract/CONTRACT.md](../contract/CONTRACT.md) and its schemas, `fixtures/`), never from `planner/` or `calib/` source. They are the independent check on what the app and calib tracks build. Builders make them pass but don't edit them. If an eval is wrong, say so with the exact check and line, and the evals owner or the integration agent fixes it.

Run everything from the repo root through the dev shell and the eval lock (three evals at a time machine-wide, docs/REFACTOR.md §7): `nix develop -c node scripts/eval-lock.mjs -- npm run eval:…` (once: `nix develop -c npm install`).

Every eval prints one line per check, `PASS|FAIL <id> <what> — <measured value>`, then `<id>: n/m checks passed`, and exits 1 on any FAIL. When a feature isn't there yet, the check fails with the reason (`hook missing: getScreenRect`, `serve.py exited (2): … unrecognized arguments: --scenes-dir`, `calib/ missing: …`) instead of crashing. Results also land in `evals/out/<eval>/results.json`.

## How they run

- **Servers:** every eval starts its own server (`planner/serve.py`, or the v2 server: below) on a free port (bound to port 0 first) with scratch `--scenes-dir`, `--layouts-dir`, `--renders-dir`, `--library-dir` and `--costs-file` under `evals/out/<eval>/server-<n>/`, and stops it at the end, also on a crash or Ctrl-C. Each eval also checks that the repo's own `scenes/`, `layouts/`, `renders/` and `library/` were left untouched.
- **Money:** always `MIDSTUDY_FAL_MOCK=fixtures/fal`, `MIDSTUDY_NO_DOTENV=1`, `NOOK_NO_DOTENV=1`, no `FAL_KEY`, and `--daily-spend-usd 0` (E1's cap test uses `0.03` with `MIDSTUDY_FAL_MOCK_COST=1`, still mocked). `startServer` refuses to start a server without the mock and a cap. Nothing reads `.env`.
- **Calibration:** `--calib "python3 fixtures/stub_calib.py"` with `MIDSTUDY_CALIB_MOCK=fixtures/calib`, so the golden photos get their true camera and depth. E1 and E6 wrap it in `evals/lib/gated_calib.py` (it logs each call, can hold a job on a gate file, and in E6 sends `align` to the real `midstudy-calib`). E2 runs the real CLI.
- **Library:** a scratch library holding the **probe box** (`probe-box`, 80 × 50 × 120 cm, magenta and unlit via `KHR_materials_unlit`, made by `evals/lib/harness.mjs`), so its silhouette is exactly its bounding box and it can't be confused with anything in the golden room.
- **Browser:** headless Chrome from the user's flake, `$PUPPETEER_EXECUTABLE_PATH` (or `MIDSTUDY_BROWSER`), through `playwright-core`, with `BROWSER_ARGS` from `evals/lib/harness.mjs`: `--use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist` (WebGL on SwiftShader) and `--enable-unsafe-webgpu --use-webgpu-adapter=swiftshader` (WebGPU on Dawn's SwiftShader adapter; the evals' `http://127.0.0.1` pages are a secure context, which WebGPU needs). `MIDSTUDY_WEBGPU=0` drops the WebGPU flags, to exercise the WebGL2 fallback. Animations and transitions are switched off. Never Helium or any browser the user browses with.
- **v2 switches** (contract §0, §5.3), read by `evals/lib/harness.mjs`, `evals/library_api.sh` and `evals/pipeline_offline.sh`; both default to `legacy` (v1), and with the defaults nothing changes:
  - `MIDSTUDY_SERVER=legacy|next`: `python3 planner/serve.py`, or `node server/src/main.ts` with exactly the same flags.
  - `MIDSTUDY_ADD=legacy|next`: the furniture CLI, which the server gets as `--midstudy-add` and E8 runs: `uv run --project pipeline midstudy-add`, or `node pipeline/src/cli.ts` with the same arguments and environment (E8 adds `NODE_USE_ENV_PROXY=1`, so Node honours the dead proxies that make any network call fail). E8's splat-thinning check calls v1's Python module; with `next` it runs the same splats through the CLI instead (a mocked SAM 3D answer of 400,000 splats).
  - Either `next` sets `MIDSTUDY_STRICT=1`: the v2 server and CLI then validate what they send and write against the schemas (contract §0), so every eval is also a contract check.
  - Each eval's first line says what it ran against, e.g. `E1 scenes-api: server legacy (python3 planner/serve.py), furniture CLI legacy (uv run --project pipeline midstudy-add)`.
  - Two E1 checks start `planner/serve.py` themselves (startup refusals); they follow `MIDSTUDY_SERVER` once they use the harness's `serverCommand()`.
- **Build:** when `scripts/build.mjs` exists, it runs once per eval process before the first server (the planner bundle in `planner/dist/`, the wasm kernels), as a check: `node scripts/build.mjs builds the planner (once per eval)`.
- **Recording:** `MIDSTUDY_RECORD_API=<absolute dir>` appends one JSON line per `/api` call made through the harness's `raw()`/`api` helpers (and E7's `add`/`call`/`wait_job`) to `<dir>/<eval>-<pid>.jsonl`; `node contract/tools/check-recordings.mjs <dir>` validates every answer, accepted request and meta header against `contract/api/routes.json`. Off by default.
- **Expectations are computed here**, never read from the planner: `evals/lib/harness.mjs` has the §4.1 projection and its inverse (checked against `truth.json` by `eval:selftest`); `evals/lib/images.py` (numpy, Pillow) judges occlusion, measures alignment and builds the align pair.
